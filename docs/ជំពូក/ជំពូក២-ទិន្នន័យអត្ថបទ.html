ជំពូក ២៖ ការធ្វើការជាមួយទិន្នន័យអត្ថបទ (Working with Text Data)

Note

ប្រភព៖ ថត ch02 និងតារាងមាតិកាក្នុង README.md របស់ upstream។

ជំពូកនេះគ្របដណ្តប់ការរៀបចំទិន្នន័យអត្ថបទសម្រាប់ LLM — ដំណើរការពីអត្ថបទឆៅទៅជា token រហូតដល់ការបង្កើត dataloader សម្រាប់ការបណ្តុះបណ្តាល។ បណ្ណាល័យពាក់ព័ន្ធសំខាន់ ដែល requirements.txt កំណត់សម្រាប់ជំពូកនេះគឺ tiktoken (>= 0.5.1)។

មេរៀនពេញលេញ (សិក្សាងាយ)

ការពន្យល់ខាងក្រោមជា អត្ថបទដើមរបស់សហគមន៍ខ្មែរ គ្របដណ្តប់គំនិតទាំងអស់នៃជំពូក ២ ជាមុនពេលអ្នកបើកមើលកូដ។

១. បញ្ហាមូលដ្ឋាន៖ កុំព្យូទ័រមិនយល់អត្ថបទទេ

បណ្តាញសរសៃប្រសាទធ្វើតែគណនាលេខ។ ដូច្នេះមុនពេលបណ្តុះបណ្តាល LLM អ្នកត្រូវបំលែងអត្ថបទ ទាំងមូលទៅជា លេខ។ បំពង់ (pipeline) នេះមាន ៤ ជំហាន៖

អត្ថបទឆៅ  ->  Tokenization  ->  Token IDs  ->  Embedding  ->  វ៉ិចទ័រលេខ

២. Tokenization — ពីអត្ថបទទៅ token

Tokenization គឺការបំបែកអត្ថបទជាឯកតាតូចៗហៅថា token។ មានវិធីសាស្ត្រសំខាន់ៗ៖

វិធីសាស្ត្រ

លក្ខណៈ

បំបែកតាមអក្សរ

vocabulary តូចបំផុត ប៉ុន្តែ sequence វែងខ្លាំង ហើយអក្សរម្តងៗគ្មានន័យ

បំបែកតាមពាក្យ

មានន័យច្បាស់ ប៉ុន្តែ vocabulary ធំខ្លាំង និងបរាជ័យលើពាក្យដែលមិនធ្លាប់ឃើញ

BPE (subword)

ដំណោះស្រាយកណ្តាល — ប្រើកំណាត់ពាក្យដែលកើតឡើងញឹកញាប់ ដូច្នេះ vocabulary មានទំហំសមរម្យ ហើយគ្រប់ពាក្យអាចបំបែកបាន

៣. ការអភិវឌ្ឍ tokenizer ជាបណ្តើរៗ

ជំពូកនេះសាងសង់ tokenizer បីកំណែ ដើម្បីបង្ហាញពីហេតុផលនៅពីក្រោយការរចនា៖

SimpleTokenizerV1 — បំបែកតាមពាក្យដោយកន្សោម regex ធម្មតា។

  • បង្កើត vocabulary ពីពាក្យដែលប្រទះឃើញក្នុងអត្ថបទបណ្តុះបណ្តាល។

  • បញ្ហា៖ បើប្រទះពាក្យថ្មីដែលមិនមានក្នុង vocabulary វានឹង បរាជ័យ។

SimpleTokenizerV2 — ដោះស្រាយបញ្ហាខាងលើដោយបន្ថែម special tokens៖

Special token

តួនាទី

<|endoftext|>

សម្គាល់ទីបញ្ចប់អត្ថបទមួយ និងការបំបែកឯកសារពីរចេញពីគ្នា

<|unk|>

ជំនួសពាក្យដែលមិនស្គាល់ (unknown)

tiktoken (GPT-2 BPE) — tokenizer ផលិតការពិតប្រាកដ អនុវត្តជាភាសា C ដើម្បីល្បឿន។ ជំពូកនេះតម្រូវ tiktoken >= 0.5.1 តាម requirements.txt។

៤. BPE ដំណើរការយ៉ាងដូចម្តេច?

Byte Pair Encoding សាងសង់ vocabulary ដោយចាប់ផ្តើមពីអក្សរតែមួយៗ រួចផ្គុំគូដែល កើតឡើងញឹកញាប់បំផុត ម្តងហើយម្តងទៀត រហូតដល់ទំហំ vocabulary គោលដៅ។

ក្បួនដំណើរការ៖

  1. ចាប់ផ្តើមដោយ vocabulary នៃអក្សរ/byte នីមួយៗ។

  2. រាប់ភាពញឹកញាប់នៃគូជាប់គ្នាទាំងអស់ក្នុង corpus។

  3. ផ្គុំគូដែលញឹកញាប់បំផុតទៅជា token ថ្មីមួយ រួចបន្ថែមវាចូល vocabulary។

  4. ធ្វើជំហាន ២–៣ ម្តងទៀត រហូតដល់ឈានដល់ទំហំ vocabulary ដែលចង់បាន។

លទ្ធផល៖ ពាក្យធម្មតា (ដូចជា the) ក្លាយជា token តែមួយ ចំណែកពាក្យកម្រត្រូវបានបំបែក ជាកំណាត់តូចៗ។ GPT-2 ប្រើ vocabulary ទំហំ 50,257 token។

Note

ចំណាំសំខាន់សម្រាប់ភាសាខ្មែរ៖ BPE របស់ GPT-2 ត្រូវបានបណ្តុះបណ្តាលលើអត្ថបទអង់គ្លេស ជាចម្បើង ដូច្នេះអក្សរខ្មែរនឹងត្រូវបំបែកជា byte ច្រើន។ នេះជាហេតុផលដែលការសាងសង់ tokenizer សម្រាប់ភាសាខ្មែរដាច់ដោយឡែកមានសារៈសំខាន់។

៥. Sliding window និង target shift

ដើម្បីបណ្តុះបណ្តាល យើងត្រូវបំលែងអត្ថបទវែងជា ឧទាហរណ៍ (samples) ប្រវែងថេរ។

អត្ថបទ៖  [t0 t1 t2 t3 t4 t5 t6 t7 t8 t9 ...]

context_size = 4, step_size = 1

sample 1:  input  = [t0 t1 t2 t3]   target = [t1 t2 t3 t4]
sample 2:  input  = [t1 t2 t3 t4]   target = [t2 t3 t4 t5]
sample 3:  input  = [t2 t3 t4 t5]   target = [t3 t4 t5 t6]

ចំណុចគន្លឹះ៖ target គឺ input រំកិលទៅមុខ ១ token។ នេះហើយជាអត្ថន័យនៃ "ការព្យាករណ៍ token បន្ទាប់" — នៅគ្រប់ទីតាំង ម៉ូដែលត្រូវទាយ token ដែលនៅបន្ទាប់។

ប៉ារ៉ាម៉ែត្រសំខាន់៖

  • context_size (ឬ max_length) — ចំនួន token ក្នុង input នីមួយៗ។ GPT-2 ដើមប្រើ 1024។

  • step_size (ឬ stride) — ចំនួន token ដែលបង្អួចរំកិលម្តងៗ។

៦. Embedding — ពីលេខទៅវ៉ិចទ័រ

Token ID គ្រាន់តែជាសន្ទស្សន៍ — លេខ 50256 មិន "ធំជាង" លេខ 1 ក្នុងន័យអត្ថន័យទេ។ ដូច្នេះយើងត្រូវបំលែងវាទៅជាវ៉ិចទ័រ។ ម៉ូដែល GPT ប្រើ embedding ពីរប្រភេទ បូកបញ្ចូលគ្នា៖

ប្រភេទ

ទំហំតារាង

តួនាទី

Token embedding

vocab_size x emb_dim

តំណាង អត្ថន័យ នៃ token

Positional embedding

context_size x emb_dim

តំណាង ទីតាំង នៃ token ក្នុង sequence

ហេតុអ្វីត្រូវការ positional embedding? ព្រោះ attention ខ្លួនឯងមិន phân biệt លំដាប់ទេ។ ការបូកបញ្ចូលគ្នា៖ x = token_emb + pos_emb

៧. DataLoader

ក្នុងការបណ្តុះបណ្តាលពិតប្រាកដ យើងមិនដំណើរការទិន្នន័យទាំងអស់ម្តងទេ។ PyTorch DataLoader ផ្តល់ឧទាហរណ៍ជា batch ដោយ៖

  • shuffle — ច្របល់លំដាប់ឧទាហរណ៍ជារៀងរាល់ epoch។

  • batch_size — ចំនួនឧទាហរណ៍ក្នុងមួយជំហាន។

  • drop_last — ទម្លាក់ batch ចុងក្រោយបើវាមិនពេញ ដើម្បីជៀសវាង tensor មានទំហំមិនស្មើគ្នា។

៨. សំណួរពិនិត្យការយល់ដឹង

ពេលអ្នកដំណើរការ notebook សូមពិនិត្យថាអ្នកអាចឆ្លើយសំណួរទាំងនេះបាន៖

  1. តើ vocab_size និង context_size កំណត់ទំហំ parameter នៃស្រទាប់ embedding យ៉ាងដូចម្តេច?

  2. តើអ្វីកើតឡើងបើ token មួយមិនមានក្នុង vocabulary?

  3. ហេតុអ្វី target ត្រូវរំកិល ១ token ជាជាង ២ ឬ ០?

  4. តើ drop_last=True ដោះស្រាយបញ្ហាអ្វី?

  5. តើអ្នកអាចគណនាចំនួន parameter សរុបនៃ embedding ទាំងពីរបានទេ?
