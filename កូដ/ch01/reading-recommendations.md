## ហេតុអ្វីត្រូវមានវិធីសាស្ត្រអាន?

សៀវភៅបច្ចេកទេសខុសពីសៀវភៅអានលេង — គោលដៅមិនមែនគ្រាន់តែអានចប់ទេ
គឺត្រូវ **ធ្វើបាន**។ អ្នកនិពន្ធបានចែករំលែកវិធីសាស្ត្រផ្ទាល់ខ្លួនដែលគាត់ប្រើ
ពេលអានសៀវភៅបច្ចេកទេសរបស់អ្នកដទៃដែរ។ វាមិនមែនជា "រូបមន្តសកល" ទេ
ប៉ុន្តែជាចំណុចចាប់ផ្តើមដ៏ល្អ។

ចំណុចសំខាន់មួយសម្រាប់សៀវភៅនេះ៖ **សូមអានតាមលំដាប់ជំពូក** ព្រោះជំពូកនីមួយៗ
ត្រូវការចំណេះដឹងពីជំពូកមុន។ កូដដែលសរសេរក្នុងជំពូក ២ ត្រូវបានយកទៅប្រើបន្តក្នុងជំពូក ៣
ហើយបន្តបែបនេះរហូតដល់ជំពូក ៧។

សម្រាប់ជំពូកនីមួយៗ សូមអនុវត្តតាមជំហានទាំង ៥ ខាងក្រោម។

## ១) ការអានលើកទី ១ — អានសុទ្ធ គ្មានកូដ

អានជំពូកទាំងមូលពីដើមដល់ចប់ **ដោយមិនទាន់សរសេរ ឬដំណើរការកូដអ្វីទាំងអស់**។

គោលដ្ឋាននៃការអានលើកនេះគឺ **យល់រូបភាពធំ (big picture) ជាមុនសិន** មុនពេលជាប់គាំង
នឹងព័ត៌មានលម្អិត។

អ្វីដែលគួរធ្វើ៖

- អានឱ្យឆ្ងាយពីកុំព្យូទ័រ។ សៀវភៅក្រដាសល្អបំផុត ប៉ុន្តែឧបករណ៍ឌីជីថលដែល
  **គ្មានការរំខាន** (បិទ browser, social media, email) ក៏ដំណើរការដែរ។
  អ្នកនិពន្ធកត់សម្គាល់ថា ទោះគាត់ប្រើ e-ink tablet តាំងពីឆ្នាំ ២០១៨ មក
  ក្រដាសនៅតែជួយឱ្យគាត់ផ្តោតអារម្មណ៍បានល្អជាង — នោះហើយជាមូលហេតុដែលគាត់
  បោះពុម្ពអត្ថបទស្រាវជ្រាវខ្លះដើម្បីអាន។
- ធ្វើឱ្យវាជាវគ្គអានខ្លី **ប្រហែល ២០ នាទី** ដែលផ្តោតអារម្មណ៍ ដោយមិនគិតច្រើនពេក
  និងមិនជាប់គាំងនឹងលម្អិតតូចតាច។
- អាច **គូសបន្ទាត់ ឬកត់ចំណាំ** ត្រង់កន្លែងដែលច្រឡំ ឬគួរឱ្យចាប់អារម្មណ៍បាន
  ប៉ុន្តែ **កុំទាន់ស្វែងរកចម្លើយ** នៅដំណាក់កាលនេះ។
- អានតែប៉ុណ្ណោះ — កុំដំណើរការកូដ។

## ២) ការអានលើកទី ២ — អានជាមួយកូដ

អានម្តងទៀត ហើយលើកនេះ **វាយកូដឡើងវិញដោយខ្លួនឯង រួចដំណើរការវា**។

ការ copy-paste កូដគឺងាយស្រួលជាង ព្រោះការវាយឡើងវិញចំណាយពេលច្រើន។
ប៉ុន្តែការវាយឡើងវិញ **បង្ខំឱ្យអ្នកគិតអំពីកូដ** ជំនួសឱ្យការគ្រាន់តែកក់ភ្នែកមើលកន្លងផុតទៅ។
នេះជាចំណុចដែលអ្នកនិពន្ធយល់ថាមានតម្លៃពិតប្រាកដ។

បើលទ្ធផលរបស់អ្នកខុសពីក្នុងសៀវភៅ សូមពិនិត្យតាមលំដាប់នេះ៖

1. សាកល្បងកូដចេញពី **ឃ្លាំង GitHub ផ្លូវការ** របស់សៀវភៅ (អាចមានកំហុសអក្ខរាវិរុទ្ធ
   ឬកំណែចាស់ក្នុងសៀវភៅដែលបោះពុម្ព)។
2. បើនៅខុសទៀត ពិនិត្យមើលថាតើវាបណ្តាលមកពី **កំណែ package ខុសគ្នា**, **random seed**,
   ឬ **CPU vs CUDA** ឬអត់។
3. បើនៅតែរកមិនឃើញ សួរអ្នកនិពន្ធដោយផ្ទាល់ — តាមរយៈ **book forum**,
   **GitHub issues/discussions** សាធារណៈ ហើយជម្រើសចុងក្រោយគឺ email។

## ៣) លំហាត់

បន្ទាប់ពីអានលើកទី ២ និងដំណើរការកូដរួច នេះជាពេលវេលាសមស្របដើម្បីធ្វើ **លំហាត់**។

លំហាត់ជួយ **ពង្រឹងការយល់ដឹង** និងអនុញ្ញាតឱ្យអ្នកសាកល្បងដោះស្រាយបញ្ហា
ក្នុងទម្រង់មានរចនាសម្ព័ន្ធគ្រាន់បើ។

- បើលំហាត់ពិបាកពេក ការមើលចម្លើយគឺ **អាចទទួលយកបាន**។
- ប៉ុន្តែសូម **ព្យាយាមដោយខ្លួនឯងឱ្យបានល្អិតល្អន់ជាមុនសិន** មុនពេលបើកមើលចម្លើយ។

ចំណាំសម្រាប់ឯកសារខ្មែរនេះ៖ ចម្លើយលំហាត់មានក្នុង notebook `*-ចម្លើយលំហាត់.ipynb`
នៃថត [`ណូតប៊ុក-ខ្មែរ/`](../../ណូតប៊ុក-ខ្មែរ) ហើយត្រូវបានសង្ខេបក្នុងភាគបន្ថែម C។

## ៤) ពិនិត្យកំណត់ចំណាំឡើងវិញ និងស្វែងយល់បន្ថែម

ឥឡូវអ្នកបានអាន បានដំណើរការកូដ និងបានធ្វើលំហាត់រួចហើយ — សូម **ត្រឡប់ទៅមើល
ការគូសបន្ទាត់ និងកំណត់ចំណាំ** ពីការអានទាំងពីរលើកមុន ហើយពិនិត្យថាតើនៅមានចំណុចណា
ដែលមិនទាន់ច្បាស់នៅឡើយទេ។

- នេះជាពេលវេលាសមស្របដើម្បី **ស្វែងរកឯកសារយោងបន្ថែម** ឬ search រហ័ស
  ដើម្បីបញ្ជាក់ចំណុចដែលនៅតែមិនច្បាស់។
- ទោះបីជាអ្វីៗច្បាស់លាស់ហើយក៏ដោយ ការអានបន្ថែមអំពីប្រធានបទដែលអ្នកចាប់អារម្មណ៍
  ក៏ជាគំនិតល្អដែរ។
- សរសេរ ឬផ្ទេរ **ចំណេះដឹងមានប្រយោជន៍, code snippet** ទៅក្នុងកម្មវិធីកត់ចំណាំ
  ដែលអ្នកចូលចិត្ត។

## ៥) យកគំនិតទៅប្រើក្នុងគម្រោងជាក់ស្តែង

ជំហានទាំង ៤ ខាងលើសុទ្ធតែអំពី **ការទទួលយកចំណេះដឹង**។ ជំហាននេះគឺអំពី
**ការប្រើប្រាស់វា**។

សាកល្បងមើលថាតើអ្នកអាចយកផ្នែកខ្លះនៃជំពូកទៅប្រើក្នុងគម្រោងផ្ទាល់ខ្លួនបានទេ
ឬបង្កើតគម្រោងតូចមួយដោយប្រើកូដក្នុងសៀវភៅជាចំណុចចាប់ផ្តើម។
សម្រាប់គំនិត សូមមើល **bonus materials** — ទាំងនោះគឺជា mini-project
ដែលអ្នកនិពន្ធបានធ្វើដើម្បីបំពេញការចង់ដឹងផ្ទាល់ខ្លួនរបស់គាត់។

ឧទាហរណ៍នៃសំណួរដែលអាចកើតឡើងបន្ទាប់ពីអានចប់៖

- បន្ទាប់ពីយល់ **multi-head attention** និងបានអនុវត្ត LLM រួច —
  តើម៉ូដែលដែលប្រើ **grouped-query attention (GQA)** ដំណើរការល្អកម្រិតណា?
- តើ **RMSNorm** ខុសពី **LayerNorm** ប៉ុន្មានពិតប្រាកដ?

 ជួនកាល អ្វីដែលមានប្រយោជន៍គឺជា **លម្អិតតូចបំផុត**។ ឧទាហរណ៍ជាក់ស្តែងមួយ
ដែលអ្នកនិពន្ធលើកឡើង៖ ការសាកល្បងថាតើការហៅ `torch.mps.manual_seed(seed)`
ដោយផ្ទាល់ ផ្តល់លទ្ធផលខុសពីការហៅតែ `torch.manual_seed(seed)` ម្នាក់ឯងឬអត់។
ការសង្កេតតូចៗបែបនេះហើយដែលជារឿយៗក្លាយជាមានតម្លៃក្នុងគម្រោងពិត។

## គំនិតបន្ថែម

គ្មានចំណុចណាមួយខាងលើជាច្បាប់តឹងរ៉ឹងទេ។

- បើប្រធានបទ **ស្គាល់ច្បាស់ ឬងាយស្រួល** សម្រាប់អ្នកហើយ ហើយអ្នកអានសៀវភៅនេះ
  គ្រាន់តែដើម្បីទទួលបានព័ត៌មានក្នុងជំពូកក្រោយៗ — ការអានរំលង (skim) គឺអាចធ្វើបាន
  ដើម្បីកុំខ្ជះខ្ជាយពេលវេលា។
- សម្រាប់ជំពូកដែល **គ្មានកូដ** (ដូចជាជំពូក ១ នេះ) ការរំលងជំហានដែលទាក់ទងនឹងកូដ
  គឺសមហេតុផលទាំងស្រុង។

សូមអានដោយរីករាយ និងរៀនសូត្រដោយជោគជ័យ!
